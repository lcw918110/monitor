# 容量摸底（实验室，不是 SLA）

单进程 + SQLite 的中心能记多少主机、保留多久，要在一台具体机器上跑完才知道。本文只说明怎么跑、旋钮是什么、结果怎么读。**不公布主机上限。** 表里的格子在真实跑完之前留空。

双中心、双活、多写者 SQLite、自动故障切换都不在这次摸底里。那些仍然不做。备份和恢复见 `docs/14-ops-runbook.md`。

## 探针做什么

`scripts/capacity_probe.py` 在**临时目录**里建一个实验室库，用中心现有的上报入口写入合成点：

- 默认调用 `center.api.handle_metrics_post`（也就是 `POST /api/v1/metrics` 用的函数），直接进 `Storage`
- `--http` 时在 `127.0.0.1` 的临时端口上挂现有 HTTP 接口，再 `POST /api/v1/metrics`，并 `GET` 主机列表、单机历史、单机时段、集群时段

它不调用诊断报告生成，不连接 `/opt/monitor`，也不往已有 `config/center.json` 的目录里写。主机 id 固定以 `capprobe-` 开头。合成点只存在于这次实验室库。

写入条数是 `--samples-per-host`，**不是**把 `retention_days` 整天写满。保留期的行数和体积是用这次测到的「每行字节」外推的。

外推：

```text
每天每台点数 = ceil(86400 / 采样间隔秒)
保留期满行数 = 主机数 × 每天每台点数 × retention_days
保留期满库体积 ≈ 保留期满行数 × (本次库文件字节 / 本次历史上报行数)
```

库文件字节含索引、主机表和 WAL，不是单条 payload 的长度。主机很少、行数也不多时，这个平均数会偏高；行数上去之后索引还会再长一点。外推用来和磁盘比，不用来写「推荐 N 台」。

时段统计一次最多读 6 万行（`PERIOD_MAX_ROWS`）。15 秒采样、保留 40 天时，单机一个月的窗口会碰到这道上限。探针若看到截断，会在输出里写「时段截断=是」。那是读路径的上限，不是又一个主机台数。

## 怎么跑

在仓库根目录：

```bash
# 冒烟：2 台 × 2 点。只证明命令能跑完。不要把输出填进下面的表。
PYTHONPATH=. python3 scripts/capacity_probe.py --smoke

# 正式实验室跑。数字换成你要估的旋钮。--samples-per-host 默认 20。
PYTHONPATH=. python3 scripts/capacity_probe.py \
  --hosts 50 \
  --interval 15 \
  --retention-days 7 \
  --samples-per-host 30

# 连 HTTP 入口一起测，并把 JSON 留下。目录必须是空的实验室目录，不能是 /opt/monitor。
PYTHONPATH=. python3 scripts/capacity_probe.py \
  --hosts 50 --interval 15 --retention-days 40 \
  --http --keep-dir /tmp/capprobe-lab --json-out /tmp/capprobe-lab.json
```

不传 `--hosts` 时按冒烟运行，避免一次误写很多行。单次写入条数默认不超过 `--max-writes`（20000）。这是防止把磁盘写满的护栏，**不是**容量结论。确认磁盘之后可以调高。

`--with-accel` 只在报文里加一块假卡，让 payload 稍大一点。它不是生产指标，也不会生成诊断报告。

探针拒绝这些路径：`/opt/monitor`、`/opt/monitor-agent`、`~/monitor`、`~/monitor-agent`，以及任何已经有 `config/center.json` 的目录。升级备份目录 `/opt/monitor-backup-...` 不在拒绝之列，但也不要把实验室库写到备份里。

## 旋钮

| 旋钮 | 含义 | 冒烟时 |
| --- | --- | --- |
| `--hosts` | 模拟主机数 | 固定 2，且不能和 `--smoke` 同时写 |
| `--interval` | 采样间隔（秒）。用来拉开时间戳，并参加外推 | 固定 15 |
| `--retention-days` | 外推用的保留天数，同时传给这次实验室 `Storage` | 固定 7 |
| `--samples-per-host` | 每台**实际写入**的点数 | 固定 2 |
| `--http` | 走本机现有 HTTP API | 关 |
| `--max-writes` | 这一次最多写多少条 | 20000 |
| `--keep-dir` | 留下实验室库供检查 | 跑完删除临时目录 |
| `--with-accel` | 假加速卡，加大一点 payload | 关 |

采样间隔 15 秒时，每天每台是 5760 点。7 天、50 台的外推行数是 50 × 5760 × 7。这只是公式，不是这次仓库已经测得的结果。

## 怎么读输出

输出里始终有这些话：实验室估算，不是 SLA；没有主机上限；双中心推迟。

正式跑（不是冒烟）时，可以看：

- **库体积外推**和中心磁盘剩余空间。升级还要再留大约 3 倍数据库（见 `docs/14-ops-runbook.md` 的磁盘预检）。外推接近剩余空间时，先缩短 `retention_days`、加大采样间隔，或减少主机。
- **写入 p95**。它如果已经接近采样间隔，单进程写库在变忙。先改间隔或主机数，不要加第二个写同一个 SQLite 的进程。
- **集群时段毫秒**和「时段截断」。截断表示读窗口碰到 6 万行，报告或时段页会少看一部分点，不等于机器离线。
- **诊断报告条数**应为 0。若不是 0，这次库被别的流程写过，结果作废。

冒烟输出只说明命令能结束。它的每行字节来自 4 行样本，不能填进结果表，也不能写进对外说明。

结论栏（实测后用自己的话写，仍不要写成 SLA）：

- 这次外推库体积：约 10.5GB（10538188800 字节）在 50 台 / 15 秒 / 40 天假设下
- 相对该机器剩余磁盘：Mac 约 1.8Ti 空闲，外推远小于本机空闲；生产中心另看其磁盘（升级预检曾见约 1.35TB 可用量级），升级还要再留约 3 倍库体积
- 写入 p95 相对采样间隔：3.007ms ≪ 15s，单进程写库很空
- 是否碰到 6 万行时段上限：否（本次读窗口未截断；外推满保留期后单机月窗仍可能碰到，见文中说明）
- 准备采用的主机规模、采样间隔、retention_days：与现场一致可继续 15s / retention_days=40；主机规模按现网约二十多台，50 台外推仅作实验室参考，尚未另定上限
