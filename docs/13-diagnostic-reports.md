# 使用诊断报告（日 / 周 / 月）

中心在本地把窗口内的原始历史上报聚合成中文诊断报告，写入 SQLite，页面和 API 只读库存结果。不依赖外部机器人，也不把已经生成的日报/周报拼成月报。

监测台页签：**使用诊断**（`/#reports`）。

## 时间窗

时区 **Asia/Shanghai**（无夏令时，UTC+8）。区间是半开的：含起点，不含结束时刻。

| 类型 | 请求窗口 | 对比窗口 |
| --- | --- | --- |
| 日报 `day` | 昨日 00:00～今日 00:00 | 再前一日 |
| 周报 `week` | 上周一 00:00～本周一 00:00 | 再前一周 |
| 月报 `month` | 上月 1 日 00:00～本月 1 日 00:00 | 再上一自然月 |

查询复用时段统计：半开结束时刻换成整数秒闭区间 `[from, to-1]`，再交给 `resolve_period_window`。若起点早于 `retention_days`，实际起点被抬高，报告抬头写明 **clamped** 和实际起点。整段都在保留期之外时返回 400，不入库、不编造。

`as_of`（Unix 秒）只用于决定「今天」落在哪一天，方便补生成上一个完整周期；不能拿它指定任意起止，也不能拿旧报告当数据源。

v1 **不自动定时生成**。在页面点「生成并保存」，或 `POST /api/v1/reports/generate`。

## 口径

与 [`docs/11-period-utilization.md`](11-period-utilization.md) 相同的样本加权（`sample_weighted`）和繁忙阈值（默认 CPU / 加速卡 ≥80%，`period_util` 可改）。

闲忙两极 **只看 CPU 和加速卡**。磁盘、内存不进闲忙。

| 判定 | 条件 |
| --- | --- |
| 高负荷 | 样本数 ≥10，且 CPU 繁忙占比 ≥40% 或 CPU P95 ≥85%；加速卡同样（有卡且样本够时） |
| 基本不用 | **当前在线**且样本数 ≥10；CPU 平均 <5% **且** 繁忙 <5%；有加速卡则加速卡平均也 <5% **且** 繁忙 <5% |
| 样本不足 | 在线但样本不够，或有卡却没有加速卡样本。不判成空闲，也不编数 |
| 离线 | 生成时刻已离线。只写末次上报时间，**不把末次快照当实时用量** |

5% 是收紧后的空闲线。更早的报告模板曾用 CPU 平均 <15%、加速卡平均 <10%，**当前产品不用那两档**。

已落入高负荷的主机不再重复算作基本不用。

磁盘单独成节：集群平均 / P95 / 最高；主机按窗口内最高 `disk_percent` 分 ≥85% 与 ≥95%（跟 `anomaly.disk_*` 一致）。多挂载的最满路径来自该窗口历史点里的 `disks[]`。历史里没有挂载列表时写「挂载样本不足」，不用生成时刻的快照回填过去。磁盘满不等于算力忙。

缺任何指标就写「样本不足」或「无加速卡」。

## 报告结构

1. 抬头（类型、时间窗、对比窗、口径、保留期裁剪）
2. 总览（在线率、集群指标、相对上一周期、一句风险）
3. 集群资源利用表
4. 主机排行（CPU、加速卡、磁盘、内存偏高、异常/离线）
5. 闲忙两极
6. 磁盘
7. 资源组（有分组时；组内仍是样本加权）
8. 诊断与建议（不根据部署日志推断「部署残留」）
9. 附录（样本数、裁剪、全量一览；完整排行见 CSV）

## API

与其它监测台接口一样：浏览器直接调用，**不另加 Token**。Agent 上报 Token 仍只校验 `POST /api/v1/metrics`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/reports/preview?period=day` | 只返回将要使用的时间窗，不计算、不入库 |
| POST | `/api/v1/reports/generate` | 正文 `{"period":"day"\|"week"\|"month","as_of":可选}`。算完写入 `diagnostic_reports` |
| GET | `/api/v1/reports` | 已保存列表（新的在前） |
| GET | `/api/v1/reports/{id}` | JSON：`markdown` 与 `payload.sections` / `rankings` |
| GET | `/api/v1/reports/{id}/markdown` | 下载 Markdown |
| GET | `/api/v1/reports/{id}/rankings.csv` | 下载主机排行 CSV |

再次 GET 不会重算。要更新数字必须再 POST 一次，会新插入一行。

## 存储

表 `diagnostic_reports`（与主机库同一个 SQLite）：周期、半开请求窗、是否裁剪、Markdown、完整 JSON。

历史点在原有趋势字段之外，增加精简 `system.disks[]`（`mount` / `percent` / `used_gb` / `total_gb`），便于点名最满挂载。没有 `disks[]` 的旧点保持原样。时段统计的 avg/P95 仍只用汇总 `disk_percent`。

单机读取上限在诊断报告里是 250000 行（时段统计接口默认仍是 60000）。触达上限时附录会写明，不从别的报告补数据。

## 页面

`/#reports`：选择日报 / 周报 / 月报，看将生成的时间窗，生成并保存，点左侧列表预览中文九节，下载 Markdown 或排行 CSV。15 秒自动刷新不会清掉正在看的报告，也不会后台重算。

实时监控、时段统计的列（规格与实时利用率分开、离线不显示末次快照数字）不受这一页影响。
