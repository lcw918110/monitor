# 对外使用手册

本文给已经装好中心的日常使用人员：看监测台、填资产、读诊断报告、改常用设置。安装、升级、备份和卸载在 [`16-external-deploy-guide.md`](16-external-deploy-guide.md)。报告口径的完整说明在 [`13-diagnostic-reports.md`](13-diagnostic-reports.md)，时段统计在 [`11-period-utilization.md`](11-period-utilization.md)，磁盘汇总在 [`12-disk-mounts.md`](12-disk-mounts.md)。

手册按现行 **v1.10.0** 编写。下面的地址把 `<中心IP>` 换成现场中心地址，端口以现场为准，默认 8080。

监测台大约每 15 秒自动刷新。启用了管理 Token 之后，改数据、部署、生成报告和保存设置都要在顶栏黄条填入这把口令；看列表、看报告、导出不需要。管理 Token 不是登录账号，全站共用一把。

## 1. 打开监测台

在浏览器打开下面三个地址。

| 入口 | 地址 | 谁常用 |
| --- | --- | --- |
| 监测台 | `http://<中心IP>:8080/` | 看实时、时段、使用诊断 |
| 客户端部署 | `http://<中心IP>:8080/deploy.html` | 添加目标机并安装采集端 |
| 设置 | `http://<中心IP>:8080/settings.html` | 保留天数、阈值、两把口令、报告推送 |

顶栏还有：总览、主机、诊断、运维、设置。监测台内部三个页签是 **实时监控**、**时段统计**、**使用诊断**。顶栏「导出 CSV」「导出 JSON」导出的是当前主机快照，不是诊断报告。

页面打不开时，先按部署手册第 11 节做健康检查，并确认本机到中心 TCP 端口的网络是通的。中心进程名对应的 systemd 单元是 `monitor-center`。

## 2. 实时监控

打开监测台后默认在「实时监控」。页上从上到下是：今日关注、异常汇总、集群即时统计、主机表、右侧主机详情。

### 2.1 在线与离线

超过 `offline_seconds` 没有上报就标为离线，默认 **90 秒**。离线主机的资源判定是「未知」：列表里不把最后一次快照的 CPU、内存、磁盘、加速卡数字当成当前利用率。它只进入今日关注里的「离线」，不会再用那次旧快照去算磁盘或负载。

今日关注按**当前快照**分成四类，点一类就筛到主机表：

| 类别 | 默认含义 |
| --- | --- |
| 离线 | 超过离线阈值没有上报 |
| 磁盘快满 | 磁盘达到异常线（默认 ≥95%）或磁盘异常 |
| 卡异常 | 加速卡健康异常 |
| 高负载 | CPU 达到异常线（默认 ≥95%），或 load1/核数、load5/核数达到 2.0 |

长期几乎不用的机器不在今日关注里算。那一项在使用诊断的「基本不用」。

### 2.2 着色

在线主机按设置里的阈值着色：偏高为黄，异常为红。未改配置时：

| 资源 | 偏高 | 异常 |
| --- | --- | --- |
| CPU 利用率 | ≥80% | ≥95% |
| CPU 负载 | load1/核数或 load5/核数 ≥ 2.0 | 没有单独的红线。load15 只展示 |
| 内存 | ≥85% | ≥95% |
| 磁盘 | ≥85%（看最满的挂载） | ≥95% |
| 加速卡利用率 | ≥95% | 没有单独的红线 |
| 加速卡温度 | ≥85°C | ≥95°C |
| 加速卡显存 | ≥90% | ≥98% |
| 加速卡健康 | Warning 等非正常 | Alarm / Critical；PCI 回退的 abnormal 算卡异常 |

读不到的负载显示 `-`，不写成 0。利用率小于 0、大于 100 或不是有限数时标为「无效」，不拿去和高低阈值比较。黄/红只改变页面颜色和今日关注，不会发邮件或短信。改这些线不会改使用诊断里的空闲线和高负荷线。

### 2.3 排序、筛选和地址

主机表点击列头，可按在线、资源判定、地址、资源组、负责人、用途、类型、CPU%、内存%、磁盘%、磁盘数、加速卡型号、加速卡使用率、负载、最近上报排序。

筛选在表头上方：搜索框、类型、资源判定、资源组、负责人。搜索框匹配主机、地址、历史 IP、负责人和用途。

主机列优先显示**完整 IP**。顺序是：手工填写的展示地址，未停用的部署清单，`host_id` 里嵌着的 IP，以及内网网卡地址。回环、链路本地，以及 `198.18.0.0/15` 这一段地址会被跳过，避免把隧道或基准测试用的地址当成主机地址。

加速卡列显示型号和数量。使用率在旁边单独一列。磁盘百分比和磁盘数也分成两列。多于一块磁盘时，百分比旁边会标出盘数。百分比取各挂载里**最满**的那一块，容量则是纳入统计的挂载相加，避免大盘把快满的小盘摊薄。哪些挂载不会计入（虚拟盘、网络盘、容器路径、小于 1 GiB 的非主路径等）见 [`12-disk-mounts.md`](12-disk-mounts.md)。

### 2.4 负责人、用途和资源组

负责人和用途是中心上的手工字段，采集端上报不会改写它们。可以按负责人筛选，也可以搜用途。

资源组在实时页点「管理分组」创建。给主机分配之后，可以用资源组筛选。分组保存在中心 SQLite 里，重启还在，**不必升级采集端**。

### 2.5 隐藏、恢复和删除

详情里「从列表隐藏」之后：

- 该机退出主机表、在线/离线统计、集群时段汇总，以及**之后**新生成的诊断报告。
- 历史上报还在。已经入库的旧报告不会自动改写，里面仍可能出现这台机器。
- 它继续上报也不会自动回到列表。
- 点「已隐藏」可以找到它并恢复。接口是 `GET /api/v1/hosts?hidden=1`。

彻底删除要在确认框输入 `delete`。对应接口是 `DELETE /api/v1/hosts/{id}?confirm=delete`。没有这句确认时接口返回 400，什么都不删。删除会连同该机历史一起去掉。

隐藏或删除时，可以同时勾选去掉部署清单里 host_id 或 IP 对得上的目标。不选的话，清单还在，下次部署仍可能再装。

## 3. 主机详情

在主机表点一台机器，右侧打开详情。已隐藏的机器不在默认列表里，但知道 `host_id` 时仍可按 id 打开。

### 3.1 手工资产和采集规格

详情把两类信息并排：

| 来源 | 内容 | 谁来改 |
| --- | --- | --- |
| 手工资产 | 负责人、用途、名称、分类、宿主机、CPU、内存、硬盘、GPU、型号或资产编号、备注、展示地址、历史 IP | 人在详情或「导入资产」里改。空字符串会清空该字段 |
| Agent 规格 | CPU 型号和核数、内存总量、磁盘分盘、加速卡型号和数量、当前利用率 | 只有采集端上报。上报不覆盖手工文字 |

磁盘详情在两块及以上时列出分盘（挂载、已用/总量、百分比），并提示最满的挂载。

### 3.2 同机更换 IP

机器还是那一台、只换了地址时，用详情「更换 IP」。先预览，确认后再写入。

- 展示地址改为新 IP。旧 IP 记在「历史 IP」（可带日期和备注）。按旧 IP 或新 IP 导入资产表都能对上这台主机。
- 监控用的 `host_id` 和历史上报都不改。
- 新 IP 上已经有的部署目标会把 `host_id` 改成这台主机，密码不动。
- 旧 IP 上属于这台主机的部署目标标为停用，不删除。停用后不再驱动展示地址，也不再进入部署。
- 「撤销更换 IP」可以回到上一次。没有可撤销记录时接口返回 400。

不要用「隐藏」代替改址。部署清单里单独把某一行标为停用，只改停用标记，不改 IP、host_id 和密码。

### 3.3 异常说明怎么读

详情和列表里的卡状态是中文说法，原始健康值仍留在数据里。常见情况：

| 看到的现象 | 含义 |
| --- | --- |
| 驱动缺失、工具不在 PATH、设备无响应 | 机器上可能有已知加速卡，但厂商工具没装好或设备没有正常响应。PCI 回退的健康状态是 `abnormal`，利用率留空，不是 0% |
| 温度偏高 / 异常 | 达到第 2.2 节的 85°C / 95°C（未改配置时）。这是页面着色 |
| 磁盘某挂载偏高 | 文案会带上最满路径，例如数据盘。磁盘满不等于这台机器的 CPU 或加速卡很忙 |
| 利用率「无效」 | 采集值不在 0～100。不参与平均，也不当成高负荷 |
| 负载为 `-` | 这一档负载没有读到，不是负载为 0 |
| 无加速卡 | 类型是 `cpu`，或探测没有认出卡。系统指标仍会上报 |

加速卡采集依赖目标机自己的工具。缺哪一种工具、PCI 如何回退，见部署手册第 3.3 节。

## 4. 时段统计

打开页签「时段统计」（地址栏 `#period`）。这里看一段时间内的利用，不和实时表堆在同一屏。

### 4.1 时间窗

预设 **1 小时、2 小时、6 小时、24 小时、7 天**，也可以自己填起止时间。

接口上的对应关系：相对窗口用 `minutes`（60 / 120 / 360 / 1440 / 10080）。不填时，时段接口默认 **120 分钟**。绝对窗口用成对的 `from_ts` 和 `to_ts`（Unix 秒）。两个都给时，以绝对窗口为准。

窗口会被裁到 `retention_days` 和当前时刻。整段都早于保留期时，接口返回 400，文案是「时间范围已超出历史保留期」，不会编一个利用率。`retention_days` 为 0 时不按天数裁剪。

### 4.2 点选主机和离线概览

选定时间范围之后，左侧最上面是**离线概览**。它给出这一窗口里有几台离线、一共几段、累计多久，以及每段的起止。没有离线段时，页面写「这一时段没有离线」。有离线时，概览写成「离线 N 台 / 总台数 · 段数 · 累计时长」，表里每台有次数、累计时长和离线时段。每段写成「起点 ~ 终点（时长）」；一直持续到窗口结束的那一段，终点写「窗口结束」。概览里每台先列出最多三段，最多列出 12 台。其余的段和其余的机器，点开该主机后在右侧看全。

左侧点一台主机，**只换右侧**「主机时段」。左侧列表的滚动位置和当前选中行保持不动，加载提示只出现在右侧。快速连点时，还没返回的上一次请求会被丢掉，右侧不会被上一台的内容盖住。定时刷新在时间窗没有变时，不重拉已经打开的趋势。

右侧先写这台机器的离线时段（每段起止和时长），再写利用率。判定和实时页的在线判定是同一条线，不另加传感器。一条上报覆盖其后 `offline_seconds` 秒（含），默认 **90 秒**。两次上报的间隔没有超过这条线，就不记一段。这台主机**第一次上报之前**的时间不算离线。离线时段不进入平均、P95 和繁忙占比，也不改变使用诊断里的闲忙两极。

窗口末尾若因为单机读取上限被截断，截断之后的时间不猜成离线。概览会写「有主机的历史上报达到读取上限，窗口末尾是否离线未判断」。口径见 [`11-period-utilization.md`](11-period-utilization.md)。

### 4.3 平均、最低、最高、P95、繁忙占比

每个指标给出：

| 字段 | 含义 |
| --- | --- |
| 平均 avg | 窗口内有效样本的算术平均 |
| 最低 min / 最高 max | 窗口内的最小、最大 |
| P95 | 95 分位 |
| 繁忙占比 busy_ratio | 样本里达到繁忙线的比例。该指标没有繁忙线时为空 |
| 样本数 | 该指标的有效样本条数 |

默认繁忙线是 CPU ≥80%、加速卡 ≥80%。页面上可以临时改。配置项在 `period_util.busy_cpu_percent` 和 `busy_accel_percent`。内存和磁盘默认不算繁忙占比。把查询参数设成负数表示该指标不算繁忙。

统计里还包括内存、磁盘利用率、load1、网络入/出向，以及加速卡在这段时间里的最高温度。小于 0 或大于 100 的利用率不进入平均、P95 和繁忙占比。

「导出 CSV」下载的是**当前这个时间窗**的时段表，和顶栏的主机快照 CSV 不是同一个文件。

### 4.4 集群汇总是样本加权

集群数字把未隐藏主机在窗口内的**原始样本合在一起**再算平均、P95 和繁忙占比。最低、最高取全部样本里的最小和最大。上报更密、在线更久的主机权重大。这不是「每台机器先算出一个平均数，再对机器台数做平均」。

已隐藏的主机不进入集群时段。单机时段仍可以按 `host_id` 查看，包括已隐藏的。各主机行带手工填写的负责人和用途。

一次时段查询默认最多读 6 万行。读到上限时，窗口后部的点不会进入这次统计。这是读路径的限制。没有读到的那一段不猜成离线。说明见 [`11-period-utilization.md`](11-period-utilization.md) 和 [`15-capacity-lab.md`](15-capacity-lab.md)。

## 5. 使用诊断

打开页签「使用诊断」（`#reports`）。中心在本机把窗口内的历史上报收成一份中文报告，写入数据库。再次打开是读已经保存的结果，不会重新计算，也不会把日报、周报拼成月报。

调度在中心进程里，不需要另配 cron。只在配置的那一分钟、进程还活着时生成**上一完整周期**。停机错过的那一分钟不补。缺的报告到页面上按窗口补「生成并保存」。

### 5.1 日、周、月

时区固定 **Asia/Shanghai**（UTC+8）。窗口含起点、不含结束时刻。

| 类型 | 默认生成时刻 | 报告覆盖的窗口 | 对比 |
| --- | --- | --- | --- |
| 日报 | 每天 00:10 | 昨日 00:00～今日 00:00 | 再前一日 |
| 周报 | 每周一 00:20 | 上周一 00:00～本周一 00:00 | 再前一周 |
| 月报 | 每月 1 日 00:30 | 上月 1 日 00:00～本月 1 日 00:00 | 再上一自然月 |

周几固定是周一，月报固定是 1 日，这两天不能改成其它日子。小时和分钟可以在设置页改，`hour` 为 0–23，`minute` 为 0–59。

页面上选日报、周报或月报，再选一个窗口日期（默认落在上一完整周期里的一天），先看将要使用的时间窗，再点「生成并保存」。同一窗口再生成会**覆盖**这一行，编号不变，来源改为手动。定时任务若发现这个窗口已经有一行（成功或失败），就跳过，不覆盖人手生成的报告。

窗口里一条上报都没有时，日、周、月报告仍然生成并入库。这一行是成功（`status=ok`，`empty=true`），不是失败。左侧列表保留它，徽章为「无数据」。右侧只留报告壳，写「没有可汇总的上报」，不把整篇「样本不足」铺开，也不把这一行从列表里拿掉。日、周、月相同。下载的 Markdown 仍含这句说明，方便存档。预览时间窗在没有上报时会附上一句「这一窗口没有上报，生成后仍会留下报告」。

窗口还没结束，或日期不合法：拒绝生成，不入库。起点早于保留期：报告抬头写明被裁短。整段都在保留期外：生成失败，列表里留下失败原因，右侧写失败原因，不编造利用率。失败和「无数据」是两回事。

### 5.2 闲忙两极

闲忙**只看 CPU 和加速卡**。磁盘和内存不进入这两极。未改配置时：

| 判定 | 条件 |
| --- | --- |
| 高负荷 | 该指标样本数 ≥ 10，并且繁忙占比 ≥ 40%，或者 P95 ≥ 85%。CPU 满足即算；有加速卡且加速卡样本也够时，加速卡同样可以单独算高负荷 |
| 基本不用 | **生成时刻**这台机器在线，样本数 ≥ 10，CPU 平均 < 5% **并且** CPU 繁忙占比 < 5%。有加速卡时，加速卡的平均和繁忙占比也要低于同样两条线 |
| 样本不足 | 在线但样本不够，或有卡却没有足够的加速卡样本。不判成基本不用，也不编数 |
| 离线 | 生成时刻已经离线。只写末次上报时间，不把末次快照当成当时的用量 |

已经算作高负荷的机器不再算作基本不用。更早模板里用过的「CPU 平均低于 15%、加速卡平均低于 10%」不是现行规则。

时段统计里的 80% 繁忙线，和这里的 5%、40%、85% 是两组配置。改时段繁忙线不会改闲忙两极。已经入库的旧报告不会自动重算，要对该窗口再生成一次。

最少样本数、空闲线和高负荷线在设置页的 `report` 段，对应 `min_samples`、`idle_avg_lt`、`idle_busy_lt`（0.05 表示 5%）、`high_busy_gte`、`high_p95_gte`。

排行和闲忙两极带负责人和用途。没填时正文写「未填」，排行 CSV 里是空字符串。隐藏若发生在生成之后，旧报告里仍可能有这台机器。

窗口在线率的算法是：该窗口内至少有一条历史上报的主机数，除以当前未隐藏主机数。采样中断算未上报。闲忙里的「离线」和「基本不用」只看生成那一刻是否在线。

### 5.3 磁盘单独成节

报告里的磁盘不参加闲忙。它单独给出集群平均、P95 和最高，并按窗口内最高磁盘百分比分档，默认 ≥85% 与 ≥95%，和实时着色的磁盘线相同。多块盘时，最满路径来自该窗口历史里的挂载列表。历史点里没有挂载列表时写「挂载样本不足」，不用生成时刻的快照回填过去。磁盘满不等于算力忙。

### 5.4 预览和下载

左侧「已保存」列出每个窗口的最新一行，并标出定时或手动，以及成功、「无数据」或失败。没有上报的窗口徽章是「无数据」。打开一份之后可以下载：

| 按钮或接口 | 得到什么 |
| --- | --- |
| 预览时间窗 `GET /api/v1/reports/preview?period=day\|week\|month` | 只看将使用的窗口，不计算利用率、不入库。另附 `sample_count` 与 `empty`。窗口内没有未隐藏主机的上报时 `empty` 为真 |
| 生成并保存 | 写入数据库。正文过长时，推送会截断，全文仍在监测台 |
| 下载 Markdown `GET /api/v1/reports/{id}/markdown` | 报告正文 |
| 下载排行 `GET /api/v1/reports/{id}/rankings.csv` | 主机排行，含负责人和用途 |

15 秒自动刷新不会清掉正在看的报告，也不会在后台重算。

## 6. 资产导入与部署页日常操作

### 6.1 导入资产

实时页点「导入资产」，选择 CSV 或 xlsx。按 IP 匹配**已经出现过的主机**，先「预览匹配」，再「写入匹配行」。空单元格不覆盖已有内容。列名含用户名、密码、口令、password、token 的整列会丢掉，不写入资产。

示例（里面的人和地址都是虚构的）在 [`../config/hosts-meta.example.csv`](../config/hosts-meta.example.csv)。手工地址、历史 IP、展示地址、`host_id` 里嵌着的 IP 都能用来匹配。

导入不会创建采集端，也不会给从未上报的 IP 变出一台在线主机。新机器要先按部署手册装上采集端，上报之后再补资产；或者机器已经在列表里再导入。

要在已经生成的诊断报告里看到新填写的负责人和用途，需要对那个窗口再生成一次。

### 6.2 部署页上的日常操作

安装步骤在部署手册第 6 节。页面在 `http://<中心IP>:8080/deploy.html`。清单和部署放在页面上方：先是「给机器装上采集」，接着是「部署清单」，「部署勾选」和「全部部署」在清单标题旁边，再往下是「部署过程」。加入机器和表格导入在清单下面。中心地址、默认账号、默认安装目录和上报间隔收在「不常改的连接」里。

- 改「中心地址」、默认 SSH 用户、端口、安装目录和上报间隔，然后点「保存连接设置」。密码框留空不会清掉已经保存的密码。地址写成 `127.0.0.1` 或 `localhost` 时，保存前会再问一次。
- 编辑某一台的 IP 或 `host_id`。另一个目标已经使用该 IP 时会拒绝保存。
- 「先测能不能连上」只检查 SSH 和目录是否可写，不代替正式部署。
- 「部署勾选」和「全部部署」都会先确认。确认文案说明将向勾选的机器，或清单里所有未停用的机器，安装或覆盖采集端（默认目录 `/opt/monitor-agent`）。已经停用的不会动。确认之后才会安装，并保留目标机上的 `config/agent.json` 与 `data/`。成功显示「部署成功」。失败短码表在部署手册第 6.3 节，短码旁边有一句可以直接照着查的说明。
- 清单里每一行的「删除」也会先确认。删除只去掉清单里的这一行，不卸载对方机器上已经装好的采集端。要卸掉采集端，到那台机器上按部署手册第 10 节执行 `uninstall.sh`。
- 「停用 / 恢复」只改变是否还参与部署，不改 IP、host_id 和密码。停用前也会确认。
- Excel/CSV 导入的是**部署清单**，和实时页的资产导入不是同一个文件。模板从「下载表格模板」取得（`/api/v1/deploy/template.xlsx`）。选择文件后会先确认。确认后只写入清单，不会马上安装。

中心地址不要使用 `127.0.0.1`。SSH 端口默认 22，产品不扫描端口。清单还在加载、加载失败或还是空的时，表格里有对应说明。

## 7. 设置页

打开 `http://<中心IP>:8080/settings.html`。页首三个入口直接跳到 **报告时刻**、**报告推送**、**管理 Token**。日常先从这三处进。中心参数写入 `/opt/monitor/config/center.json`（生产目录）。管理 Token 和 Webhook 写在数据库，不进这个文件。

每一项在页面上有说明。没改过的项显示「默认」。单条「恢复默认」、整组恢复和全部恢复，点下去之前都会再确认。单条确认写明只改这一项。全部恢复不清管理 Token，也不清 Webhook。字段表见 [`../config/center.example.md`](../config/center.example.md)，样例 JSON 见 [`../config/center.example.json`](../config/center.example.json)。

### 7.1 常用参数

| 分组 | 常用项 | 默认 | 保存后 |
| --- | --- | --- | --- |
| 保留与清理 | `retention_days` | 7 | 立即生效。只删过期历史上报，不删已生成的报告 |
| 保留与清理 | `offline_seconds` | 90 | 立即影响在线判定 |
| 异常着色 | CPU、内存、磁盘、加速卡的黄/红线 | 见第 2.2 节 | 立即用于实时页。不改变诊断报告的闲忙线 |
| 诊断报告阈值 | 空闲、高负荷、最少样本 | 见第 5.2 节 | 立即用于**之后**的生成。旧报告不重算 |
| 时段利用率 | CPU / 加速卡繁忙线 | 80 | 立即用于时段统计。不带动闲忙线 |
| 报告时刻 | 日 00:10、周一 00:20、每月 1 日 00:30 | 上海时间 | 立即用于调度。错过不补 |
| 上报 Token | `token` | 空 | 立即只作用于指标上报。页面不回显明文 |
| 服务 | 监听地址、端口、数据目录 | `0.0.0.0` / 8080 / `data` | 只写入文件。要重启 `monitor-center` 才换，这不是升级 |

手改中心机上的 `center.json` 后，必须重启 `monitor-center` 才会重读。设置页保存则不需要为了阈值去重启。

### 7.2 报告推送

渠道是企业微信、钉钉、飞书，填写机器人 Webhook。未启用或没填地址时，不向外发请求，报告照常入库。定时生成和页面「生成并保存」成功后都会尝试推送。推送失败不影响报告入库，正文过长会截断。

| 渠道 | 发送形式 | 现场要注意 |
| --- | --- | --- |
| 企业微信 | markdown | 使用机器人 Webhook |
| 钉钉 | markdown | 当前版本不算加签。请在机器人安全设置里用自定义关键词，关键词包含「诊断」 |
| 飞书 | text | 使用机器人 Webhook |

只接受 http 或 https。读取设置时只看到打码后的地址（主机名和密钥末四位）。完整地址留在中心数据库里，备份也会带上。还没有填写地址就打开推送时，页面会再问一次：开启后也不会把报告发出去。清空 Webhook 用页面上的「清空 Webhook」，清空前也会确认。

### 7.3 管理 Token

建议在中心端口对他人可见之前就设上。未设置时，写操作不校验。

- 保存的是 SHA-256。页面不再显示明文。设置页的管理 Token 和页面上方黄条是**同一把**口令。黄条只在当前标签页记住，关掉标签页后要再填。更换或清空时，先在黄条填入当前 Token，再点「本页使用」。
- 启用后，部署、改主机、改地址、导入、生成报告、保存设置都要带当前 Token。错误或缺失时接口返回 401，代码 `management_token_required`。
- 它不能代替 Agent 上报 Token，上报 Token 也不能用来改设置。
- 忘记时，在中心机执行部署手册第 5 节的 `sqlite3` 删除语句，然后立刻重新设置。生产库路径是 `/opt/monitor/data/monitor.db`。

## 8. 常见问题

**某一天没有上报，诊断报告会消失吗？** 不会。日、周、月都会生成并入库。列表徽章是「无数据」，右侧报告壳写「没有可汇总的上报」。这是成功留下的空报告，不是失败。整段超出保留期才会失败，并在列表里写明原因。

**从部署清单里删掉一台，采集端会卸掉吗？** 不会。删除只去掉清单里的这一行，点之前会再确认。目标机上的 `monitor-agent` 还在。要卸掉，到那台机器上执行部署手册第 10 节的 `uninstall.sh`。

**主机表一直是空的。** 中心页面能开，只说明中心进程在。列表要等采集端成功上报。看部署清单是不是「部署成功」，目标机上 `monitor-agent` 是否在跑，以及采集端配置里的中心地址是不是 `http://<中心IP>:8080` 而不是 `127.0.0.1`。上报 Token 若已设置，两边必须一致。

**主机一会在线一会离线。** 默认大约 90 秒没有上报就离线。采集端重启、崩溃、或到中心的网络抖动，都会让它在这条线附近来回。到目标机看 `journalctl -u monitor-agent`。没有 systemd 时看安装目录下的 `run/agent.log`。把离线秒数改得很小会让抖动更明显。

**磁盘很满，是不是算力很忙？** 不是。磁盘百分比看的是空间。使用诊断里的高负荷和基本不用只看 CPU 和加速卡。磁盘在报告里单独一节。一块数据盘满了，CPU 仍可能很低。

**加速卡写着样本不足，或利用率为空。** 有卡但窗口里有效样本少于最少样本数（默认 10）时，不判闲忙。厂商工具缺失时，PCI 回退只说明「有这块设备、健康异常」，利用率留空，不会用 0% 去把机器说成很闲。类型选成 `cpu` 的机器本来就不采加速卡。

**密码是明文存在库里的。** 部署清单和默认 SSH 密码以明文写在中心数据库，页面不回显，但 `data/monitor.db` 和每份备份里都有。Agent 上报 Token 以明文写在 `config/center.json`。管理 Token 只存哈希。资产导入会丢弃凭据列，部署清单不走那条规则。请限制中心机和备份目录的读权限。这是现行产品的保存方式。

**填了负责人，旧报告里还是「未填」。** 已入库的报告不自动改。对该窗口再点一次「生成并保存」。

**隐藏了还出现在昨天的报告里。** 隐藏只影响之后的新报告和当前列表。旧报告保持生成时的内容。

**想看一个月的报告，抬头说被裁短。** `retention_days` 默认 7，早于保留期的样本已经删了。把保留天数加长只能保住之后的新样本，补不回已经删掉的点。

**设置了管理 Token，页面仍能看数。** 读接口本来就是开放的。Token 只挡住写操作。这不是多用户登录。

**没有收到告警短信或邮件。** 产品没有这条通道。实时页只用颜色。报告推送只在设置了 Webhook 且生成成功时，把报告正文发到企业微信、钉钉或飞书。

**能不能再搭一台中心自动顶上？** 现行版本不做双中心、双活和自动切换。备份与恢复由人按部署手册第 9 节执行。

## 9. 主要只读 API 速查

下面都是 GET，启用管理 Token 之后仍然可以直接读。把主机 `host_id` 和报告 `id` 换成现场值。完整接口表，包括部署、隐藏、改址和生成报告等写接口，在 [`README.md`](../README.md) 的「主要 API」。写接口在启用管理 Token 后要带请求头 `X-Management-Token`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/health` | 健康检查。`ok`、`version`、`name` |
| GET | `/api/v1/hosts` | 未隐藏主机。`?hidden=1` 只看已隐藏，`?include_hidden=1` 含全部 |
| GET | `/api/v1/hosts/{id}` | 详情，含手工资产和采集规格 |
| GET | `/api/v1/hosts/{id}/history` | 趋势。不带时间时默认 60 分钟 |
| GET | `/api/v1/hosts/{id}/period-stats` | 单机时段。`minutes` 或 `from_ts`/`to_ts` |
| GET | `/api/v1/period-stats` | 集群时段，样本加权。响应里的 `offline` 是这一窗口的离线概览（台数、段数、累计时长、每段起止） |
| GET | `/api/v1/stats` | 集群即时统计 |
| GET | `/api/v1/anomaly` | 异常判定汇总 |
| GET | `/api/v1/groups` | 资源组列表 |
| GET | `/api/v1/export/hosts.csv` | 当前主机快照 |
| GET | `/api/v1/export/period-stats.csv` | 当前查询参数下的时段表 |
| GET | `/api/v1/reports/preview?period=day\|week\|month` | 时间窗预览，不计算 |
| GET | `/api/v1/reports` | 已保存的诊断报告列表 |
| GET | `/api/v1/reports/{id}` | 报告 JSON，含 Markdown |
| GET | `/api/v1/reports/{id}/markdown` | 下载 Markdown |
| GET | `/api/v1/reports/{id}/rankings.csv` | 下载主机排行 |
| GET | `/api/v1/settings` | 是否已设置管理 Token、推送渠道、打码后的 Webhook，以及中心参数。不返回两把 Token 的明文 |

示例：

```bash
curl -sS "http://<中心IP>:8080/api/v1/health"
curl -sS "http://<中心IP>:8080/api/v1/hosts"
curl -sS "http://<中心IP>:8080/api/v1/period-stats?minutes=120"
curl -sS "http://<中心IP>:8080/api/v1/reports/preview?period=day"
```
